# ПУТИ DX9 → VULKAN → WINE: карта стеков, ограничители, обходные пути отображения

Проект: SSAO (FidelityFX CACAO) для Lineage 2 (UE2, D3D9) под Wine/Linux.
Дата: 06.11.2026. Проверено на системе: Arch, wine (стек Proton-подобный),
GPU AMD RX 6400 (RADV NAVI24), gamescope 3.17, DXVK 3.1 (наш форк cacao-3.1).

---

## 1. КАРТА СТЕКОВ РЕНДЕРИНГА D3D9-ИГР ПОД WINE

```
                        ┌─ игра (L2.exe, D3D9 API)
                        │
   [A] wine builtin ────┤  wined3d → OpenGL (GLX/EGL) → Mesa → GPU
   [B] DXVK (наш путь) ─┤  d3d9.dll (форк DXVK) → Vulkan ICD → RADV → GPU
   [C] d8vk ────────────┤  D3D8 → DXVK (для старых игр; L2 не нужен)
   [D] dgVoodoo2 ───────┤  d3d9.dll (wrapper) → D3D11 → DXVK d3d11 → Vulkan
   [E] wined3d Vulkan ──┤  экспериментальный бэкенд wined3d (Wine 8+), незрелый
                        │
   поверх любого из [B..D]:
   [F] vkBasalt         │  Vulkan layer, post-process ПОСЛЕ игры (без depth)
   [G] ReShade          │  hook DLL / Vulkan layer (depth зависит от стека)
   [H] gamescope        │  композитор-микродисплей: headless/nested, PipeWire
   [I] внешний постпроц ┤  PipeWire-стрим → внешний обработчик → дисплей
```

Для L2 реальны: [A] wined3d-GL (дефолт wine), [B] DXVK (наш форк — рабочий),
[D] dgVoodoo2 (теоретически), [F..I] — надстройки.

## 2. ОГРАНИЧИТЕЛИ ПО СТАДИЯМ (где именно «заперто»)

### 2.1 Доступ к depth buffer — ГЛАВНЫЙ ОГРАНИЧИТЕЛЬ

| Стек | Доступ | Как | Статус |
|---|---|---|---|
| [B] DXVK | Только изнутри DXVK | VkImage глубины — внутренний объект; `SAMPLED_BIT` DXVK добавляет сам, но публичного API нет | **наш путь: форк** (SetDepthStencilSurface + SetTransform кэш) |
| [A] wined3d GL | Только изнутри wined3d | depth attachment FBO; GL-постпроцесс = форк wined3d | теоретически, бессмысленно (нет compute-модели старее GL430, и всё равно форк) |
| [D] dgVoodoo2→D3D11 | **доступна ReShade** | depth — обычная D3D11-текстура, ReShade addon читает штатно (D3D11 — лучший кейс ReShade) | альтернатива БЕЗ форка DXVK |
| [F] vkBasalt | нет | layer видит только swapchain-изображения | тупик (проверено исторически) |
| [I] внешний | нет | за пределами процесса игры есть только цвет | только цветовые эффекты |

Вывод: глубина либо «форк стека», либо «обёртка, меняющая API на D3D11».

### 2.2 Точка внедрения постпроцесса

| Стек | Точки | Ограничители |
|---|---|---|
| [B] DXVK-форк | (1) present-blitter (наш текущий), (2) mid-frame pass до UI (возможно в форке), (3) своя очередь после игры | (1) затрагивает UI и леттербокс — лечится координатами источника; (2) требует знать RT-состояние в момент триггера |
| [D] ReShade | стандартный хук D3D11 present + шейдеры | watermark, оверхед, dgvoodoo-специфика |
| [I] внешний | всё, что угодно | +1..3 кадра латентности, нет depth |

### 2.3 Замеченные специфичные ограничители L2 (проверено логами/дампами)

1. **Порядок пассов кадра**: матрица воды [6.31]/[4.16] прилетает ДО рендера
   геометрии мира → «первый не-мировой трансформ» = не конец мира.
   Фикс: цепочка только по UI-орто (коммит 46d25aad).
2. **Две мировые проекции за кадр** (бит-разные) — memcmp-кэш ненадёжен,
   гвард «одна цепочка на Present» обязателен.
3. **UI рисуется поверх мира в том же backbuffer** — present-композит
   затемняет и UI. Обход: mid-frame композит до UI (см. §4.B) или маска.
4. **Вода переиспользует depth** (чередование «сцена/очищено» к моменту
   Present) — поэтому сэмплируем на триггере, а не на Present.
5. **Скайбокс**: дальше ~1600 юнитов AO гасится фадаутом — корректно.
6. **UE2 baked lightmaps** — двойное затемнение; darkMask (0.3) сглаживает.
7. **descriptor heap DXVK 3.x** несовместим с классическими дескрипторами
   CACAO (`dxvk.enableDescriptorHeap=False`) — глобально чуть медленнее
   биндинг-модель; миграция CACAO на heap-биндинги снимет ограничение.
8. **GameGuard-подобные проверки** (элмор): НЕ заменять dxgi.dll, держать
   стоковый wine dxgi; наш путь — только d3d9 через WINEDLLOVERRIDES.

✓ хоткей, тюнинг, телеметрия

✗ глубина только на триггерах-эвристиках кадра

### [D] dgVoodoo2 → D3D11 → DXVK(d3d11) → ReShade — запасной путь БЕЗ форка
✓ ReShade на D3D11 читает depth надёжно; MXAO/HBAO/SSAO шейдеры готовы
✓ никакого форка DXVK — апдейты DXVK без портов
✗ dgvoodoo2 под wine для UE2 — неизвестно (проверять отдельным тестом:
  d3d9.dll dgvoodoo в папку игры + d3d11/дxgi DXVK в префиксе)
✗ качество: dgvoodoo транслирует FF-пайплайн в шейдеры — возможны отличия
  (матрицы, туман, альфа-тест), watermark, +5..15% оверхед
✗ ReShade в MMO — сетевой трафик отключает depth (исторический факт для L2!)
  — риск повторения «depth-блока» уже на другом стеке
Вердикт: план «Б», если форк зайдёт в тупик.

### [F] vkBasalt — тупик (depth нет; проверено 04.2026)
### [E] wined3d Vulkan — незрелый, D3D9 не покрывает — не трогать
### [I] внешний постпроцесс по PipeWire — демо/верификация, не игровой путь
Латентность 1–3 кадра; depth недоступен; но ПОЛЕЗНО как «чистый экран
без помех» для автотестов (уже используется в tools/l2bg_run.sh).

## 4. ОБХОДНЫЕ ПУТИ ОТОБРАЖЕНИЯ (для нашего форка) — ранжирование

### A. Present-blitter композит (текущий) — работает
AO умножается на весь кадр в момент Present. Минусы: UI затемняется,
масштабирование/леттербокс требовали координат источника (исправлено).
Плюсы: минимальный риск, всё уже работает.

### B. Mid-frame композит в момент world→UI — лучшее качество (ПЛАН)
В момент триггера (первый UI-орто после мировой проекции) вместо/вместе с
compute-цепочкой отрисовать полноэкранный pass `color *= ao` В САМ
backbuffer, до того как игра нарисует UI. Дает:
- UI не затемняется вовсе,
- никаких буквбоксов/масштабных сдвигов,
- композит на «живом» кадре, а не на Present-копии.
Требует: графический пайплайн в d3d9_cacao (fullscreen-треугольник +
blending), знание текущего RT/viewport в момент триггера, аккуратную
работу с DXVK-состоянием RT. Риск: средний. Эффект: заметный (UI-артефакты
уходят полностью).

### C. Depth-снапшот на триггере — страховка от переиспользования depth
Копия глубины в СВОЙ image в момент триггера (m_depthCopy уже создан, не
используется). Блокировалось device-lost на 2.7.1 (ломал layout-трекинг).
На 3.1 (unified layouts + notifyExternalDepthLayout) возможно — но сейчас
сэмплинг работает, копия не нужна. Держать как запасной ход.

### D. Миграция CACAO на heap-биндинги DXVK 3.x
Снимает `enableDescriptorHeap=False` (глобальный перф-лимитер) — чистый
перф-выигрыш для всей игры. Работа: переписать set-layouts/биндинги на
descriptor buffer API. Приоритет: после подтверждения мирового фика.

### E. Внешний дисплей-путь (PipeWire) — только инфраструктура тестов
Играть через внешний постпроцесс нецелесообразно (латентность, нет depth),
но связка gamescope-headless+PipeWire — наша тестовая платформа
(инструменты l2bg_*).

## 5. ЧТО ПОЧИНЕНО/ИЗВЕСТНО В ТЕКУЩЕМ БИЛДЕ (кратко)

| Проблема | Корень | Фикс |
|---|---|---|
| «0 изменений» на логине | сила 0.25 слишком мала | strength 0.5 |
| «пятна»/чёрные кадры | реверс-depth констант (ошибочный) | возврат mul/(add−d) |
| мерцание (период-2) | адаптивная ветка q3 читает прошлый кадр | неадаптивные q0/q1/q2 |
| «в мире нет AO» | цепочка по водному триггеру = скайбокс-only depth | триггер только UI |
| середина мира без AO | фадаут до 800 юнитов | SDK-фада до 1600 |
| «полоска» сверху | AO по координатам экрана | координаты источника + guard |
